# 📘 התקנון שלנו — עוזרת מידע מבוססת RAG לתלמידות תיכון

> **הבהרה חשובה:** המסמכים בתיקיית `data/` הם **מסמכי דוגמה בדיוניים** שנוצרו לצורך בדיקת המערכת בלבד.
> הם אינם תקנון רשמי של בית ספר אמיתי, ו"תיכון נוף הגבעות" הוא בית ספר בדיוני.

## 1. תיאור הפרויקט ומטרתו

פרויקט לימודי קטן שמדגים מערכת **RAG (Retrieval-Augmented Generation)** באמצעות **LlamaIndex**.
תלמידה שואלת שאלה בעברית על תקנון בית הספר ונהליו (איחורים, היעדרויות, הגשת עבודות, ציוד אבוד וכו'),
והמערכת עונה **אך ורק על סמך תוכן המסמכים שהועלו**, ומציגה מתחת לתשובה את מקורות המידע (שם הקובץ, מספר עמוד אם קיים, והקטע עצמו).

## 2. הטכנולוגיות שנבחרו

| רכיב | בחירה |
|---|---|
| שפת פיתוח | Python 3.13 |
| ספריית RAG | LlamaIndex |
| Embedding Model | `text-embedding-3-small` (OpenAI) |
| LLM | `gpt-4o-mini` (OpenAI) |
| Chunking | `SentenceSplitter` — 512 טוקנים, חפיפה 50 |
| Vector Database | ChromaDB מקומי במצב Persistent (`chroma_db/`) |

| ממשק | Streamlit, עברית, RTL |
| קריאת קבצים | `PDFReader` ו-`DocxReader` של LlamaIndex (על בסיס `pypdf` ו-`docx2txt`), קריאה ישירה לקובצי TXT |

## 3. ארכיטקטורת RAG בקצרה

```text
            ┌──────────── תהליך א' — Ingestion ────────────┐
 קובץ ──► זיהוי סוג ──► Reader ──► טקסט + Metadata ──► SentenceSplitter ──► Embeddings ──► ChromaDB
                                                                        (text-embedding-3-small)   (chroma_db/)

            ┌──────────── תהליך ב' — Query ────────────┐
 שאלה ──► בדיקת תקינות ──► Embedding לשאלה ──► חיפוש סמנטי (5 מקטעים) ──► gpt-4o-mini + הוראות ──► תשובה + מקורות
```

המודל אינו "יודע" את התקנון. בכל שאלה המערכת שולפת את המקטעים הדומים ביותר לשאלה ושולחת למודל רק אותם,
יחד עם הוראות מחייבות לענות רק על סמך המקטעים.

## 4. תהליך טעינת המסמכים (Ingestion)

1. **קבלת קובץ** — מהממשק (העלאה) או מתיקיית `data/` (`python ingestion.py`).
2. **בדיקות מקדימות** — סיומת נתמכת (PDF/DOCX/TXT), קובץ לא ריק, גודל סביר, והתאמה בין הסיומת לתוכן (למשל PDF חייב להתחיל ב-`%PDF`).
3. **קריאה** — `PDFReader` מחזיר מסמך נפרד לכל עמוד יחד עם `page_label`; `DocxReader` לקובצי Word; קובצי TXT נקראים ב-UTF-8 (ואם לא — בקידוד העברית של Windows).
4. **Metadata** — לכל מסמך נשמרים: שם הקובץ המקורי, סוג הקובץ, טביעת אצבע (SHA-256) של התוכן, ומספר עמוד ב-PDF.
5. **Chunking** — `SentenceSplitter(chunk_size=512, chunk_overlap=50)`. כל מקטע יורש את ה-Metadata של המסמך.
6. **מזהים עקביים** — מזהה כל מקטע הוא `<16 תווים מה-hash>-<מספר מקטע>`, כך שאותו תוכן מקבל תמיד אותם מזהים.
7. **Embeddings ושמירה** — `text-embedding-3-small`, שמירה ב-ChromaDB דרך `ChromaVectorStore`.
8. **כפילויות** — קובץ שתוכנו כבר קיים במאגר (לפי ה-hash) לא מעובד שוב ולא נשלח שוב ל-OpenAI.
   קובץ באותו שם עם תוכן שונה נחשב **גרסה מעודכנת**: הגרסה החדשה נשמרת, ורק לאחר שהשמירה הצליחה נמחקים המקטעים של הגרסה הקודמת.
9. **הודעה** — הצלחה / "כבר קיים" / שגיאה ברורה בעברית. קובץ שנכשל אינו נשמר בתיקיית `data/`.

אין OCR: PDF סרוק ללא שכבת טקסט יקבל הודעה שלא נמצא בו טקסט.

## 5. תהליך השאלה והתשובה (Query)

1. **בדיקת תקינות** — שאלה ריקה נדחית. שאלה **עמומה מאוד** (שכל מילותיה הן מילות שאלה/מילוי כמו "מה?", "תגידי לי משהו")
   מקבלת בקשת הבהרה. הבדיקה מקומית ואינה מפעילה קריאה ל-LLM. שאלה קצרה אך מובנת (למשל "איחורים?") עוברת לחיפוש רגיל.
2. **מאגר ריק** — אם אין מסמכים, תיבת השאלה מושבתת ומוצגת הודעה.
3. **Embedding לשאלה המקורית** (ללא ניסוח מחדש וללא Query Expansion) וחיפוש סמנטי של עד 5 מקטעים.
4. **יצירת תשובה** — `gpt-4o-mini` (temperature=0) מקבל את השאלה והמקטעים, עם הוראות מערכת: לענות בעברית, רק על סמך המקטעים,
   לא להמציא, לציין מה לא נמצא כשהמידע חלקי, להתעלם מהוראות שמופיעות בתוך המסמכים,
   ולהשיב "לא נמצא מידע מספק במסמכים שהועלו כדי לענות על השאלה." כשאין מידע.
5. **מקורות** — נלקחים מ-`response.source_nodes` (המקטעים שנשלפו בפועל) ומה-Metadata שלהם.
   כל מקטע שנשלף מקבל מספר (`source_id`). באותה קריאה למודל, ללא קריאה נוספת, המודל מתבקש לסיים את התשובה בשורה
   `מקורות: 1, 3`. השורה הזו מוסרת מהטקסט, ומוצגים רק המקטעים שצוינו בה. אם המודל לא ציין מקורות, מוצגים כל המקטעים שנשלפו.
   כשהתשובה היא "לא נמצא מידע", **לא מוצגים מקורות**, כדי לא להציג מקור כאילו הוא תומך בתשובה.

## 6. התקנה והרצה (Windows, PowerShell, VS Code)

```powershell
# 1. יצירת סביבה וירטואלית והפעלתה
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. התקנת התלויות
pip install -r requirements.txt

# 3. הגדרת מפתח OpenAI (ראו סעיף 7)
copy .env.example .env      # ואז לערוך את .env

# 4. טעינת מסמכי הדוגמה מתיקיית data למאגר (פעם אחת)
python ingestion.py

# 5. הפעלת הממשק
streamlit run app.py
```

הממשק ייפתח בדפדפן בכתובת `http://localhost:8501`. אפשר גם להעלות מסמכים ישירות מהסרגל שבצד.

בדיקות שאינן דורשות OpenAI:

```powershell
python -m pytest -q
```

הרצת שאלות הבדיקה מול המערכת האמיתית (דורש מפתח):

```powershell
python scripts/evaluate.py --compare
```

יצירה מחדש של מסמכי הדוגמה (לא חובה — הם כבר קיימים ב-`data/`; דורש Microsoft Word לצורך ה-PDF):

```powershell
pip install -r requirements-dev.txt
python scripts/create_sample_docs.py
```

## 7. הגדרת מפתח OpenAI

המפתח נקרא ממשתנה הסביבה `OPENAI_API_KEY`, שנטען מקובץ `.env` בתיקיית הפרויקט:

```text
OPENAI_API_KEY=sk-...
```

- קובץ `.env` נמצא ב-`.gitignore` ואין להעלותו לשום מקום.
- המפתח אינו כתוב בקוד ואינו מודפס ללוגים.
- אם המפתח חסר — הממשק מציג הודעה מתאימה ומשבית את השאלות וההעלאה.
- מפתח שגוי, חריגה ממכסה או בעיית רשת מוצגים כהודעה ברורה בעברית ולא כ-Traceback.

**פרטיות:** טקסט המסמכים נשלח ל-OpenAI לצורך יצירת Embeddings, והשאלה יחד עם המקטעים שנשלפו נשלחים למודל `gpt-4o-mini`
לצורך ניסוח התשובה. הקבצים אינם נשלחים לשום שירות חיצוני אחר.

## 8. שמירת ChromaDB

- המאגר נשמר בתיקייה `chroma_db/` (אוסף בשם `school_documents`, מרחק Cosine).
- לאחר סגירת התוכנית והפעלתה מחדש, המסמכים זמינים מיד לחיפוש — **אין אינדוקס מחדש** ואין יצירת Embeddings חוזרת.
- הרצה חוזרת של `python ingestion.py` מדלגת על קבצים שכבר קיימים במאגר.
- המאגר לעולם אינו נמחק אוטומטית. כדי להתחיל מאפס יש לסגור את המערכת ולמחוק ידנית את התיקייה `chroma_db/`.

### 9.3 שאלות הבדיקה מול המערכת המלאה (הורצו בפועל עם OpenAI)

בדיקות שבוצעו עם המפתח:

- **Ingestion אמיתי:** `python ingestion.py` יצר Embeddings ל-24 מקטעים (7 + 7 + 10) ושמר אותם ב-`chroma_db/`.
- **שמירה לאחר הפעלה מחדש:** הרצה נוספת בתהליך חדש זיהתה את שלושת הקבצים כ"כבר קיים" ולא שלחה דבר ל-OpenAI.
- **ממשק עם תשובות אמיתיות** (Streamlit `AppTest`, מפתח ומאגר אמיתיים): הסרגל הציג 3 מסמכים, תיבת השאלה הייתה פעילה,
  שאלה רגילה קיבלה תשובה עם מקור (`תקנון_נוכחות_ואיחורים.pdf · עמוד 1`), שאלה ללא תשובה ושאלה עמומה הוצגו ככרטיס הודעה ללא מקורות,
  ההיסטוריה נשמרה (6 הודעות אחרי 3 שאלות), ולא הייתה אף שגיאה.

השאלות מוגדרות ב-`scripts/evaluate.py`. התוצאות הגולמיות המלאות (תשובות, מקטעים שנשלפו, ציוני דמיון ואילו מקורות הוצגו) נמצאות ב:
- `docs/evaluation_raw_before_fixes.md` — ההרצה הראשונה, לפני התיקונים.
- `docs/evaluation_raw.md` — ההרצה הסופית.

ציון הדמיון הוא `exp(-מרחק cosine)`, כפי שמחושב ב-`ChromaVectorStore`.

**השוואה Top-K=2 לעומת Top-K=5** (אותן שאלות, אחרי התיקונים): עם K=2 שאלות 3, 4 ו-6 נכשלו ("לא נמצא מידע"),
כי המקטע הרלוונטי דורג במקום 3–4. בשאלה 2 עם K=2 המודל החיל את כלל החפצים יקרי הערך על מעיל, וזו תשובה שגויה.
התוצאה מאשרת שברירת המחדל K=5 עדיפה עבור המסמכים האלה.

## 10. בעיות שהתגלו ושיפורים שבוצעו

כל הבעיות שלהלן התגלו בפועל, בבדיקות או בהרצת שאלות הבדיקה.

1. **רווחים חסרים בטקסט שחולץ מה-PDF.** בבדיקת החילוץ התקבל למשל `עד20  דקות`, `בין08:00`, `פרק4`:
   `pypdf` השמיט את הרווח בין מילה עברית למספר והוסיף רווחים כפולים.
   **שיפור:** הפונקציה `normalize_pdf_text` מוסיפה רווח בין אות עברית לספרה ומאחדת רווחים (רק בקובצי PDF), ונוספה בדיקה לכך.

2. **אין חיבור ל-OpenAI במחשב הפיתוח.** גם עם מפתח שגוי התקבלה "שגיאת חיבור" במקום שגיאת 401, למרות ש-`curl` הגיע לשרת.
   הסיבה: הרשת עוברת דרך סינון NetFree, שמשתמש בתעודת CA בלי הרחבת key usage. Python 3.13 מפעיל כברירת מחדל את הבדיקה
   המחמירה `VERIFY_X509_STRICT` ודוחה את התעודה.
   **שיפור:** `config.make_http_client()` יוצר לקוח HTTP שמבטל רק את הדגל המחמיר, ושומר על אימות שרשרת התעודות ושם השרת
   (כמו ב-Python 3.12). לאחר התיקון התקבלה שגיאת 401 אמיתית, וה-Ingestion והשאלות עובדים.

3. **Streamlit שולח נתוני שימוש כברירת מחדל** ("Collecting usage statistics").
   **שיפור:** נוסף `.streamlit/config.toml` עם `gatherUsageStats = false`.

4. **הוצגו מקורות שאינם קשורים לתשובה** (שאלה 1, הרצה ראשונה): התשובה התבססה על מקטע אחד, אבל הוצגו כל 5 המקטעים שנשלפו,
   כולל "פורמט הגשת קבצים" ו"אוכל ושתייה". ניסיתי לבדוק אם סף דמיון יכול לסנן אותם, והתברר שלא: מקטעים לא קשורים קיבלו
   כ-0.58–0.60, ומקטע רלוונטי בשאלה 4 קיבל 0.528.
   **שיפור:** המקטעים ממוספרים (`source_id`), והמודל מציין באותה קריאה על אילו מקטעים התבסס. מוצגים רק המקטעים שצוינו.
   **תוצאה:** בשאלה 1 מוצג כעת מקור אחד במקום 5. בכל השאלות שנענו הוצגו רק מקטעים קשורים.

5. **תשובת "אין מידע" כשיש מידע חלקי** (שאלה 6, הרצה ראשונה): המקטע עם "יום הלימודים מתחיל בשעה 08:00" דורג ראשון,
   ובכל זאת המודל השיב "לא נמצא מידע". הכלל "אם אין מידע השיבי רק את המשפט הזה" גבר על כלל התשובה החלקית.
   **שיפור:** ניסוח מחדש של ההוראות: משפט "אין מידע" מותר רק כשאף קטע אינו קשור לאף חלק של השאלה; אחרת חובה לתת תשובה חלקית
   ולציין מה חסר. **תוצאה:** "יום הלימודים מתחיל ב-08:00; לא נמצא מידע על שעת הסיום ביום רביעי".

6. **החלת כלל על מקרה שהוא אינו מכסה** (שאלה 2, הרצה שנייה): אחרי תיקון 5, המודל ענה שהמעיל "נשמר בכספת המזכירות עד סוף השנה".
   הכלל הזה נכתב על חפצים יקרי ערך בלבד, ואילו בגדים נשמרים עד סוף החודש ואז נתרמים. זו תשובה שגויה, גרועה מ"אין מידע".
   **שיפור:** נוספה הוראה להחיל כלל רק על המקרים שהוא מתאר במפורש. **תוצאה:** עם K=5 התשובה חזרה ל"לא נמצא מידע".
   עם K=2 הטעות עדיין מופיעה, ולכן היא מתועדת כמגבלה.

7. **סימני פיסוק שזזו ב-PDF שיבשו את משמעות המשפט** (שאלה 3): במקטע הופיע `של 3 .ימים רצופים ומעלה מחייבת לצרף לטופס אישור רפואי`.
   הנקודה עברה לתחילת המילה שאחרי המספר, כך שנראה שהמשפט נגמר אחרי "3". גם פסיקים זזו (`4.5 ,פעילות`).
   **שיפור:** `normalize_pdf_text` מסירה נקודה או פסיק שמודבקים לתחילת מילה עברית, כי בעברית זה אף פעם אינו מיקום תקין.
   מקטעי ה-PDF נוצרו מחדש פעם אחת באופן ידני (מחיקת 10 המקטעים של הקובץ והוספתם מחדש). **תוצאה:** הטקסט במקטע תקין.
   התשובה לשאלה 3 עדיין נכונה רק חלקית (ראו 9.3), ולכן התיקון שיפר את איכות הטקסט אך לא פתר את השאלה.

8. **בדיקה שלא הניבה שיפור — הסרת שם הקובץ מטקסט ה-Embedding.** השערתי שהקידומת `file_name: ...` שמופיעה בכל מקטע
   "מטשטשת" את ההבדלים בין המקטעים. בדקתי את דירוג המקטעים הרלוונטיים עם ובלי הקידומת, בלי לשנות את המאגר.
   הדירוג כמעט לא השתנה (למשל, המקטע הנכון לשאלה 2: מקום 9 לעומת 10). **לכן לא שיניתי את הקוד.**

9. **מקטעים קטנים בעברית ובקצה עמוד** (תצפית, ללא שינוי בהגדרות). טקסט עברי "יקר" בטוקנים, ולכן מקטע של 512 טוקנים מכיל
   רק כ-450–550 תווים, וסעיף אחד עלול להתפצל בין שני מקטעים (כך קרה בסעיף 4 על ציוד אבוד). ב-PDF כל עמוד מעובד בנפרד,
   כך שבסוף עמוד 1 נוצר מקטע של 70 תווים. לא שיניתי את גודל המקטע או את החפיפה, כי לא התקבל אישור לכך.

## 11. מגבלות המערכת

- **אין OCR:** PDF סרוק (תמונה) לא ייקרא, ותוצג הודעה מתאימה.
- **שליפה בעברית עם ניסוח רחוק מהמסמך:** `text-embedding-3-small` מבחין בצורה חלשה בין מקטעים בעברית. ציוני הדמיון צפופים
  (כ-0.52–0.67), ושאלה בניסוח יומיומי ("שכחתי את המעיל") עלולה לא לשלוף את הסעיף הנכון ("ציוד אבוד", "פינת אבדות").
  במצב כזה המערכת משיבה "לא נמצא מידע", אף שהמידע קיים. ההחלטות שהתקבלו בפרויקט (ללא Query Expansion, Reranking או Hybrid Search)
  לא מאפשרות לטפל בזה. **עצה למשתמשת:** לנסח מחדש עם מילים מהתקנון.
- **שאלות שדורשות כמה סעיפים** (למשל מחלה + מבחן שהוחמץ) עלולות לקבל תשובה חלקית, כי שאילתה אחת שולפת רק חלק מהסעיפים הרלוונטיים.
- **המודל עלול להחיל כלל על מקרה שהוא אינו מכסה.** ההוראות צמצמו את הבעיה, אבל בהרצת Top-K=2 היא עדיין הופיעה (ראו סעיף 10.6).
- **PDF בעברית:** סדר המילים נשמר, ופיסוק שזז לתחילת מילה מתוקן, אך שורות עדיין נשברות באמצע משפט וסוגריים עלולים להופיע הפוכים.
- **זיהוי שאלה עמומה** מבוסס על רשימת מילים, ולכן אינו מושלם. שאלות גבוליות יעברו לחיפוש, ושם המודל יענה או יחזיר "לא נמצא מידע".
- **בחירת המקורות** מבוססת על ציון המודל עצמו. אם המודל לא מוסיף את שורת המקורות, מוצגים כל המקטעים שנשלפו.
  כשהתשובה היא "לא נמצא מידע", לא מוצגים מקורות בכלל.
- **שינוי בקוד הקריאה** (כמו תיקון הטקסט ב-PDF) אינו מעדכן אוטומטית מקטעים שכבר שמורים, כי זיהוי הכפילות מבוסס על תוכן הקובץ.
  כדי לעדכן יש למחוק ידנית את `chroma_db/` ולהריץ שוב `python ingestion.py`.
- **היסטוריית השיחה** נשמרת רק במהלך הסשן בדפדפן. כל שאלה נענית בנפרד, בלי הקשר של שאלות קודמות.
- **תלות ב-OpenAI:** נדרשים חיבור אינטרנט ומפתח בתוקף, ויש עלות שימוש קטנה.
- **עדכון קובץ** מזוהה לפי שם הקובץ. קובץ עם תוכן חדש בשם אחר יתווסף כמסמך נוסף.
- אין ממשק למחיקת מסמכים. אפשר לאפס את המאגר רק ידנית, במחיקת `chroma_db/`.
